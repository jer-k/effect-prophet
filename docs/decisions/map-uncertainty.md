# EP-072 — MAP predictive uncertainty contract

**Status: Accepted engineering decision.** The implementation owner selects the contract below; user statistical expertise or an additional user approval is not required. This decision gates the **linear/flat EP-073–076 slice only**. Logistic work already present is an experimental EP-077–079 extension, not a prerequisite for completing EP-072–076. EP-080 statistical reporting and EP-081 benchmarks are later work, not acceptance gates for this decision. The [caller-owned data-preparation policy](data-preparation-boundary.md) governs all inputs.

## Scope and reference

The reference is unmodified [Python Prophet 1.4.0 `forecaster.py` at `abf69a215604afcaa7ecb4359f592d13bf6dea9f`](https://github.com/facebook/prophet/blob/abf69a215604afcaa7ecb4359f592d13bf6dea9f/python/prophet/forecaster.py): `set_changepoints` (around 467–504), `fit` (around 1400–1454), `predict_uncertainty` / `sample_posterior_predictive` (around 1672–1787), `sample_model` / `sample_predictive_trend` (around 1788–1922), the vectorized alternatives, and `percentile` (around 2169). Generate reference fixtures only in the pinned release container, never from a patched checkout.

EP-073–076 support `linear-piecewise-map` and `flat-map` with resolved fixed additive/multiplicative seasonalities, events and regressors, target scaling and saved-model replay. `linear-trend` OLS and the teaching constant model are **unsupported** for MAP simulation: do not infer a noise scale. Existing `predict` remains point-only. No fit-time samples, new Layer, JS numerical simulator, implicit schedule, imputation or new persistence fields are approved. The separately implemented logistic branch is provisional until its own tickets are accepted; this ADR does not require its completion.

## Selected predictive process

Use Prophet 1.4.0's **continuous-time scalar** `sample_predictive_trend` process, not the default `predict(..., vectorized=True)` grid approximation. For each complete ordered batch, normalize timestamps with stored training origin/scale so training ends at `t=1`; set `h=max(0,max(t)-1)`. For each sample draw one shared future path:

1. With `r` **resolved candidate** changepoints (including fitted zero deltas), draw `K ~ Poisson(r*h)`; place `K` independent uniform times in `(1,1+h)`, then sort them.
2. Draw independent `D_j ~ Laplace(0,b)`, where `b=mean(abs(deltaOutput/targetScaling.scale))+1e-8` in **normalized target units**. For `r=0` or `h=0`, draw no future events.
3. At each row, evaluate the fixed historical piecewise trend and add `targetScaling.scale * sum_j D_j max(0,t-u_j)` to its **restored output-unit** trend `G`. Flat growth always uses its fixed trend.
4. Hold known feature effects fixed and draw independent observation noise per row/sample: `Y=G*(1+M)+A+noiseScale*Z`, `Z~Normal(0,1)`. `M` is dimensionless, `A` and `noiseScale` are output units. Do not scale noise by `M`, sample fitted coefficients, simulate future covariates or replace small fitted noise with a residual estimate.

A sample column is one path across the entire request; equal timestamps have equal latent linear trend, while supplied features and independent observation errors may differ. Preserve row order, historical rows and duplicates without sorting. The package accepts complete canonical UTC rows and explicit schedules; callers own source-data cleaning, sorting/exclusions, timezones and future inputs.

**Deliberate Prophet differences:** Python's normal `predict` calls a different vectorized grid/centered-logistic implementation; no default-output parity is claimed. Python can sort frames; we preserve prediction order. Prophet creates a private changepoint at zero when none are requested, then folds its delta into `k` and zeros delta after fit. An actually empty resolved candidate set here has `r=0`, not the release's artificial rate of one. No phantom candidate or noise is manufactured on reload. Python uses NumPy randomness; our seeded draws are not sample-by-sample identical. Unsupported regressor-predictor sampling, MCMC parameter/seasonality uncertainty, and guarantees of nominal interval coverage are excluded.

Return exactly `S` trend and value draws in output units, row-major at `row*S+sample`. Intervals reduce **the same samples** into equal-tailed empirical quantiles at `(1-width)/2` and `(1+width)/2` by linear interpolation at index `(S-1)*q`; `S=1` gives equal bounds. Changing width or output mode does not consume a different random stream. Neither the point forecast nor every trajectory must lie inside marginal bands.

## Reproducibility and numerical policy

Require an explicit uint32 seed, including zero. Defaults: `samples=1000`, `intervalWidth=0.8`, `output="intervals"`; supported count `1..2048`, width finite and strictly `(0,1)`, output `"intervals" | "samples"`. Reject fractional, out-of-range and unknown options. Results carry `prophet-map-scalar-xoshiro128ss-v1`. The RNG is local Rust state; there is no OS entropy, ambient `Math.random`, Effect Random, Python call, or TS simulation fallback.

The versioned algorithm expands a seed into four words with successive wrapping SplitMix32 steps (`x += 0x9e3779b9`; `z=(x^(x>>>16))*0x85ebca6b`; `z=(z^(z>>>13))*0xc2b2ae35`; `z^(z>>>16)`) and runs xoshiro128** (`rotl(s1*5,7)*9` with the standard four-word xor/shift transition). Uniforms use `(word+0.5)/2^32`, strictly between zero and one. Laplace uses inverse CDF; Normal uses Box–Muller and discards the paired variate. Poisson sums inversion counts for successive chunks of rate at most 16. Per sample consume Poisson uniforms, location uniforms, increment uniforms, then row-ordered Normal pairs; flat/no-point/historical paths skip the future-path draws. Integer overflow wraps where specified; numerical invalidity or exhausted work fails the **whole** call, never truncates, clips, retries or drops draws. The Rust implementation and independently calculated Python integer check agree on first five words:

| uint32 seed  | first five xoshiro128** output words                       |
| ------------ | ---------------------------------------------------------- |
| `0`          | `3809008728, 1133695204, 53579671, 2891528803, 139681546`  |
| `4294967295` | `835879718, 1921286648, 2356205009, 1885780724, 980451116` |

The replay guarantee is **same build/algorithm**, same complete model, ordered rows, seed and options, including JSON save/reload in that build. No cross-algorithm, cross-version, NumPy-seed, different-libm, row-permutation, split-request or horizon-extension draw identity is promised. An algorithm change that changes consumption or output requires a new simulation identity.

Bounded requests: at most 10,000 rows, 2,048 samples, 1,000,000 `N*S` cells, 10,000 stored changepoints, future horizon 20 training spans and `r*h<=256`; cap accumulated sampled new points at 1,000,000 and Poisson inversion iterations at 2,000,000 per call. Check arithmetic before large sampler allocations and use fallible Rust reservation. The 64 MiB check concerns sampler arrays and quantile scratch, **not** a total process-RSS promise: fixed-feature matrices, deterministic predictions, WASM frame copies and runtime overhead are additional. The two `N*S` f64 sample arrays alone use at most 16 MiB; synchronous WASM cannot be preempted by an Effect timeout. These are safety/work policy caps, not performance guarantees; EP-081 may report measured costs without blocking this decision. Any change to draws or limits that affects replay requires a new version.

## Public API, failures and tracing

`predictUncertainty(model, rows, {seed, samples?, intervalWidth?, output?})` returns `Effect<UncertaintyResult, InputValidationError | PredictionError, never>`. Results discriminate `kind: "intervals" | "samples"`, include exact sample count and simulation identity, width for intervals and caller-owned buffers for samples. Bad syntax/options/required future bounds or feature alignment are indexed `InputValidationError`. Invalid model, unsupported family, nonfinite draw, WASM integration/protocol and simulation-limit errors use `PredictionError` with stable reasons; runtime causes stay non-enumerable and out of portable fields.

**Request-level error shape decision:** retain the existing required `PredictionError.timestamp` without introducing a new error family in EP-072–076. For a nonempty whole-request limit or backend failure it contains the **actual first requested timestamp as a request anchor**, not the row that caused the failure; messages must not attribute fault to that row. Indexed nonfinite draws use their actual row. Empty requests return after options parsing and never require an anchor. A future separate request-scoped error would be a versioned API change, not a silent optional timestamp.

Precedence is row syntax → options (even for empty rows) → valid empty result → parsed model → supported uncertainty kind → complete aligned future rows/bounds → resource preflight → one coarse WASM call → checked frame and owned result. Missing future inputs win over budget/runtime errors; invalid model wins over supported-row alignment; unsupported OLS wins over semantic future-row validation. A valid empty request bypasses model and runtime. WASM direct calls return bounded status frames: success `[0,output,N,S,...]`, invalid request `[1]`, invalid model `[2]`, resource exhaustion `[3]`, nonfinite result `[4,row,sample]`. Malformed frames translate to typed protocol failure, never unchecked partial success. Even an invalid deterministic timestamp at the direct WASM boundary returns `[1]`; the adapter rejects the formerly emitted `[1,row]` shape as malformed. Public row parsing excludes that direct-invalid-timestamp path.

Name the public operation `Prophet.predictUncertainty` with `Effect.fn` and the complete coarse setup/load/execute/decode boundary `effect-prophet.wasm.simulate` with `Effect.withSpan`. No boundary span for validation, empty or preflight exits. Span attributes are stable bounded operation/backend/model/output names and row/sample counts; never observations, timestamps, coefficients, payloads, seeds, causes or secrets. Typed failures preserve their original failure and active parent span; applications, not the library, configure exporters.

## Evidence and downstream reconciliation

The [committed, hashed fixed-state fixtures](../../integration/fixtures/prophet-1.4.0/map-uncertainty.json) and [real generated-WASM comparison](../../integration/tests/prophet-1.4.0/map-uncertainty.test.ts) cover the release's `vectorized=False` linear/flat distributions, one fixed mixed-regressor linear case and a **separate, optional** logistic reference. Authored parameters, seed, sample count, output-unit noise, method and absolute moment/quantile tolerances are recorded in each case. The linear/flat cases freeze mean ≤0.09, trend-variance ≤0.014, value-variance ≤0.07 and quantile ≤0.16 absolute deviations; these are fixed-state distribution comparisons, not fitted-optimizer or population coverage guarantees. Independent compound-Poisson variance is `scale²*2*r*b²*h³/3`, with value variance `(1+M)² Var(G)+noiseScale²`; native tests exercise it alongside RNG integer vectors and forced hinge arithmetic. `npm run fixtures:generate` is the only permitted way to refresh fixture JSON; `npm run fixtures:check` verifies byte identity and integration comparisons.
