# Operational limits and evaluation workload

Public fitting, prediction and MAP uncertainty currently call **synchronous WASM on the calling thread**. Effect fibers, timeouts and interruption do not preempt a running synchronous WASM call or turn it into CPU parallelism. Applications own process/worker isolation, termination, schedules and their tracer/exporter configuration. The library emits bounded public/integration spans, not a profiler for Rust optimizer phases. For the existing input boundaries, see [data and edge cases](data-and-edge-cases.md), [model persistence](model-persistence.md) and [uncertainty](../modeling/uncertainty.md).

[Stage H evaluation follows an approved design contract](../decisions/evaluation-and-selection.md). The pure `planRollingOrigin` API plans bounded rolling-origin cutoffs without WASM or fitting. Public `crossValidate` refits and predicts **sequentially** for each fold using the supplied `FittingBackend` Layer, optionally adding a seeded MAP simulation per fold for complete value intervals; it stops at the first typed fold error without returning partial results. Multi-candidate searches (EP-088) are not implemented. Cost grows with candidate count, fold count, summed training-row visits, summed assessment forecast instances, feature/point complexity and sample count. Those are distinct workload axes, not a promise that an Effect timeout can stop a large search. Planning/resource failures must occur before a fold starts. A failed fold stops direct cross-validation; search may record a typed candidate failure and proceed to the next candidate under its explicitly selected policy. Search never yields worker isolation or a fitted winner.

Budget ceilings in the ADR (history, folds, candidates, aggregate work and per-call sampler limits) are safety caps rather than recommended production load or performance guarantees. Direct interval mode preflights at most 8,000,000 aggregate assessment-row × sample cells, and each fold obeys Stage G's 10,000-row/1,000,000-cell limits; model-dependent horizon/parameter limits still fail during the exact fold simulation. The [benchmark suite](../../benchmark/README.md) reports only correctness-eligible public workloads with recorded release-build and platform provenance; the Stage H performance ticket EP-090 has not yet supplied evaluation timings. No EP-090 evaluation benchmark or statistical accuracy guarantee exists yet; do not plan throughput or accuracy around the point interface without your own workload evidence. In production, isolate expensive synchronous requests at the application boundary and choose a real external process deadline if cancellation is essential.
