# Prepare complete rows and choose forecast dates

The [EP-092 decision](../decisions/data-preparation-boundary.md) keeps source cleanup and prediction schedules with the caller. `fit` and `predict` take **model-ready** rows, not nullable source records. The package models accepted data; it neither repairs rejected data nor promises accurate extrapolation merely because rows parse. See the [Python Prophet 1.4.0 compatibility matrix](../compatibility/prophet-1.4.0.md) for numerical support by model family.

Malformed rows and missing required future values do not create a WASM boundary span. A source failure before either public call cannot create a _library_ span. We do not trace omitted values, timestamps, covariates, source records or errors as span attributes.

## Application workflow

The [typechecked built-package example](../../examples/data-policy.ts) uses a source-specific tagged union: `observed` contains a complete `EncodedObservation`, while `missing-target` carries only a source timestamp. It counts exclusions, deliberately omits the **entire** missing-target row, splits complete retained observations into training and holdout, fits, then predicts explicit holdout instants using their known complete regressor values. It neither invents a missing target nor fills unknown future covariates. Run `npm run example:data-policy` (builds the package and executes the recipe); `npm run example:data-policy:typecheck` checks it against built package declarations.

For an actual CSV/database/API, the application must _first_ parse and classify source records under its own error policy. Excluding an outlier, keeping a revision, aggregating repeated measurements, or deciding that a null target means “not observed” are domain decisions. Sort, aggregate and deduplicate **before** `fit`; do not assume dropping rows preserves enough usable training history. Python's retained `history_dates` is not recreated: a removed source row cannot silently affect a library-provided future schedule because there is no such schedule.

Choose prediction instants deliberately. Adding `86_400_000` ms advances one fixed UTC duration, not one local civil day, a weekday or a calendar month. For month-start/end, business-day or timezone-aware schedules, choose a caller-controlled calendar/timezone implementation (including ambiguous/nonexistent DST times and versioned timezone data), then convert instants to canonical UTC timestamp strings. Do not infer a schedule from the last few training rows, extrapolate into unobserved daily hours of a sparse series, or assume pandas `MS`/offset alias semantics. Each chosen timestamp must become a **complete** future row with the known regressors, conditions, capacity and any explicitly required floor; the library does not forecast these values. Historical timestamps are allowed and are not reconstructed automatically.

An accepted row only passes structural and model-specific checks: two points may be far too few for changing trends, seasonal Fourier components, high-dimensional or collinear features. Binary/constant regressors can retain identity but their individual coefficients may not be identifiable. Logistic bounds constrain the trend, not a total with additive or negative/greater-than-one multiplicative effects. Negative targets can be valid in permitted growth/scaling paths; constant/zero data can invoke a shortcut or a typed numerical failure, not a general accuracy promise. No outlier clipping, robust likelihood, anomaly detector, frequency inference or future-regressor prediction is provided.

`fit` parses observation syntax and ordering, then options, resolves seasonalities and supported combinations, checks for at least two rows, verifies explicit changepoints/bounds, aligns conditions and regressors and only then enters fitting WASM. A malformed observation thus wins over bad options, an unsupported flat configuration can win over short history, and a valid single-row supported request fails as insufficient observations rather than silently expanding the history. `predict` parses row syntax, returns immediately for an empty request, validates the model, then checks bounds/conditions/regressors before entering prediction WASM. Keep application/source errors distinct from these typed library errors.
