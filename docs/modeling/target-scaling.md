# Target scaling

`effect-prophet` implements the nonlogistic target-scaling behavior of the pinned Python
`prophet==1.4.0` release. Scaling is train-only state: prediction rows never influence it and a
saved model never recomputes it.

## Public modes

MAP configurations accept:

```ts
{
  scaling: "absmax";
} // Python Prophet default
{
  scaling: "minmax";
}
```

An explicit scaling option on otherwise featureless linear input selects linear piecewise MAP,
because Python Prophet applies scaling inside its prior-informed model. Featureless linear input
without `scaling` or `map` retains this package's existing OLS route. Flat growth always uses the
flat MAP model and supports both modes.

Logistic floor and capacity scaling is not part of this nonlogistic contract.

## Train-only equations

For finite training targets `y`:

```text
absmax:
  offset = 0
  scale = max(abs(y))

minmax:
  offset = min(y)
  scale = max(y) - min(y)

if scale == 0:
  scale = 1

z = (y - offset) / scale
```

The target collection must be nonempty. `offset` must be finite and `scale` must be finite and
positive. An overflowing minmax range is a typed numerical fitting failure; it is not replaced by
an alternate subtraction order, infinity, or absmax scaling.

The fallback scale of one preserves Python Prophet's preprocessing for zero and constant targets.
It does not bypass each MAP model's constant-target shortcut or noise policy.

## Output-unit state and reconstruction

MAP optimization and priors operate in scaled coordinates. Fitted coefficients and observation
noise are then multiplied by `scale` before entering the TypeScript model. Trend intercept/level
is stored relative to `offset`:

```text
linear trend = offset + intercept + slope*t + H*delta
flat trend   = offset + level
additive     = X*beta
value        = trend + additive
```

The offset is added exactly once to trend. It is never added to seasonal, event, regressor, or
noise values. This distinction matters because minmax centering changes the MAP objective and can
produce different fitted coefficients from absmax.

Every fitted MAP model stores immutable state:

```ts
interface TargetScaling {
  readonly mode: "absmax" | "minmax";
  readonly offset: number;
  readonly scale: number;
}
```

Portable payloads encode the same object. Legacy flat and linear MAP payloads without
`targetScaling` decode as absmax with offset zero and `scale = fitSummary.valueScale`; decoding
does not load WASM or refit.

## Rust/WASM protocol

Legacy exports remain available with their original absmax frames. Production adapters use the
explicit scaled exports:

- `fit_flat_map_with_scaling`
- `predict_flat_map_with_scaling`
- `fit_piecewise_map_with_scaling`
- `predict_piecewise_map_with_scaling`
- `fit_piecewise_map_with_features_and_scaling`
- `predict_piecewise_map_with_features_and_scaling`

Scaling mode is integer code `0` for absmax and `1` for minmax. A scaled fit success is:

```text
[0, mode, offset, scale, ...legacySuccessWithoutStatus]
```

Flat fit success therefore has width `12 + K`, where `K` is the Fourier coefficient count.
Featureful piecewise fit success has width `16 + 2*C + K`, where `C` is the resolved changepoint
count and `K` includes all seasonal, event, and regressor columns.

Scaled prediction receives `mode`, `offset`, and `scale` before relative output-unit model state.
Its success frame is unchanged:

```text
[0, ...rows of trend, additive, value, named components]
```

Unknown/nonintegral mode codes and nonfinite or nonpositive stored scales are invalid requests.
Finite targets whose minmax range is unrepresentable use status `9` for flat fitting and status
`10` for piecewise fitting. Prediction metadata failures use the existing invalid-model status.
No finite failure frame contains NaN or infinity.

## Evidence

`integration/fixtures/prophet-1.4.0/target-scaling.json` is generated by the pinned release and
contains absmax/minmax preprocessing for positive, negative, mixed, zero, constant, and tiny-range
targets. It also contains fitted minmax linear and flat MAP cases, including a linear combination
of seasonality, custom event, and additive regressor.

Fixture generation canonicalizes fitted optimizer values to at most 12 significant digits. Rust
unit tests independently cover hand calculations, constant fallback, overflowing finite extremes,
projection, metadata validation, and actual generated WASM calls.

## Tracing

Entered MAP WASM boundaries retain `effect-prophet.wasm.fit` and
`effect-prophet.wasm.predict`. They include the bounded
`effect_prophet.scaling.mode` attribute. Targets, offsets, scales, coefficients, names, payloads,
and runtime causes are never span attributes.
