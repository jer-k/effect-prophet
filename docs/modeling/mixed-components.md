# Mixed additive and multiplicative MAP components

This document fixes the mixed-component numerical contract implemented by the Rust/WASM backend.
It targets the objective, preprocessing, initialization, and prediction behavior of unmodified
Python Prophet 1.4.0 at commit
[`abf69a2`](https://github.com/facebook/prophet/tree/abf69a215604afcaa7ecb4359f592d13bf6dea9f).
It does not port CmdStan's Newton or L-BFGS implementations.

## Modes and feature order

Every resolved seasonal, event, and regressor component has exactly one mode:
`additive` or `multiplicative`. Every column belonging to one named component has the same mode.
Columns retain the established seasonal → event → regressor order; mode resolution never reorders
coefficients. Conditional masks are applied to seasonal Fourier columns before fitting or
prediction.

Let `X_a` be the resolved feature matrix with multiplicative columns zeroed, and let `X_m` be the
same matrix with additive columns zeroed. In scaled target coordinates,

```text
z = (y - offset) / scale
g = trend in scaled coordinates
factor = X_m * beta
mu = g * (1 + factor) + X_a * beta
```

The summed negative log posterior, up to constants independent of optimized parameters, is

```text
J = N*log(sigma) + ||z-mu||²/(2*sigma²)
  + (m²+k²)/(2*5²)
  + sum(abs(delta_j)/changepointPriorScale)
  + sum(beta_l²/(2*priorScale_l²))
  + sigma²/(2*0.5²)
```

Linear growth uses `g=m+k*t+H*delta`. Reduced flat growth uses `g=m`; the prior-only `k` and
`delta` parameters from the upstream Stan model are eliminated at their modes. All optimization
parameters are dimensionless. Additive coefficients are multiplied by target scale when stored;
multiplicative coefficients remain dimensionless.

## Deterministic optimizer

Python Prophet delegates MAP optimization to CmdStan, selecting Newton below 100 observations and
L-BFGS otherwise. This package follows the existing MAP compatibility policy: it copies Prophet's
objective and quantified numerical behavior, not CmdStan's implementation.

Mixed fits use deterministic block-coordinate updates. Initialization matches Prophet:

- linear `m` and `k` use the endpoint line in scaled coordinates;
- flat `m` is the mean scaled target;
- deltas and feature coefficients start at zero;
- `sigma` starts at one.

One complete update performs:

1. With trend fixed, update every feature coefficient. An additive column uses `X[:,j]`; a
   multiplicative column uses `g*X[:,j]`. Gaussian-prior coordinates have their exact ridge
   conditional update.
2. With coefficients fixed, update trend coordinates using
   `q=1+X_m*beta`. The effective trend columns are `q`, `q*t`, and `q*H[:,j]`.
   Intercept and slope use Gaussian-prior coordinate updates; deltas use exact soft-thresholding
   for their Laplace prior.
3. Update positive observation noise with the exact conditional update

   ```text
   sigma² = 2*RSS / (N + sqrt(N² + 16*RSS))
   ```

Each finite coordinate update minimizes its conditional objective. A complete update must not
materially increase the objective. Convergence uses the existing absolute-plus-relative parameter
change controls and records a complete mixed gradient/KKT residual. No global optimum or unique
component decomposition is claimed. Iteration exhaustion, noise collapse, and non-finite state are
typed failures; there is no OLS, ridge, Newton, or L-BFGS fallback.

Exact constant histories retain Prophet's explicit shortcut: endpoint/mean level, zero rate,
deltas and feature coefficients, and scaled noise `1e-9`.

All-additive requests continue through the established additive kernels and retain their existing
method identities. A request containing at least one multiplicative component uses a separately
identified mixed optimizer.

## Prediction and units

Prophet restores the trend before composing multiplicative effects:

```text
trend = offset + scale*g
additive = scale*(X_a*beta)
multiplicative = X_m*beta
value = trend*(1+multiplicative) + additive
```

For nonzero offsets this deliberately differs from `offset + scale*mu`, which is the restored
fitted likelihood mean. Both values are tested independently.

An additive named component exposes an output-unit `value`. A multiplicative named component
exposes a dimensionless `factor` and an output-unit `contribution=trend*factor`. Factors are not
clamped at `-1`, and final forecasts are not constrained positive.

For a standardized regressor, divide its stored coefficient by the stored training standard
deviation. Additive results are output-units per original regressor unit; multiplicative results
are factor per original regressor unit. The stored mean remains an explicit centering reference,
not a causal interpretation.

## Reference evidence

[`mixed-map.json`](../../integration/fixtures/prophet-1.4.0/mixed-map.json) is generated by the
pinned offline Prophet environment. It separates a hand-authored fixed-trend objective/gradient
case from linear and flat fits produced with explicit CmdStan Newton optimization. Fitted values
are canonicalized to at most 12 significant digits and Fourier values to 12 decimal places.
Fixture agreement is cross-optimizer evidence, not bitwise optimizer identity.
